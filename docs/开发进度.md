## P3 · 数据驱动框架 ✅

**做了什么**
- `autoload/data_manager.gd`（全局单例 DataManager）：游戏启动时把 9 张 CSV 读入内存，提供角色/技能/敌人/AI/掉落/元素/经验查询接口。
- `scripts/entities/stat_formula.gd`：属性派生公式集中处（一级属性 → HP/MP/ATK/MATK/DEF/SPD/暴击/闪避）。
- `scripts/entities/unit.gd`：统一战斗单位（角色按等级派生属性，敌人读固定值），预留装备加成接口。
- `tests/test_p3.gd` + `tests/test_p3.tscn`：带断言的自动化验证脚本。
- `run_tests.bat`：双击即可重跑验证。
- `scenes/stat_panel.tscn` + `scripts/stat_panel.gd`：图形化属性面板（三角色属性卡 + 等级滑块实时刷新）。
- `run_stat_panel.bat`：双击打开图形化面板。

**这一部分的作用**
把 P2 的「纸面数值」变成游戏能实际调用的数据——相当于给游戏装了「仓库管理员（读表）+ 计算器（属性派生）」。这是 P4 战斗核心的地基：战斗里的每个数字都将从这里取。

**可视化 / 可观察结果**
- **图形化属性面板**：双击 `run_stat_panel.bat`，弹出窗口并排显示凛/苍/澪三张属性卡（生命/能量/物攻/异攻/防御/速度/暴击/闪避），拖动「等级」数字(1~20)可实时看到属性随等级成长——直观验证「数据驱动 + 属性派生」。场景为 `scenes/stat_panel.tscn`，脚本 `scripts/stat_panel.gd`。
- **命令行测试**：双击 `run_tests.bat`，控制台逐条打印检查项，每项通过显示 `[OK]`，末尾显示 `结果：全部通过 [PASS]`；可看到凛 Lv1（HP=225 ATK=32…）与 Lv10（HP=486 ATK=71.6…）的派生属性。

**如何验证**
- 命令行：
  ```
  Godot ... --headless --path D:\Qoder_game --import          # 首次建立类缓存
  Godot ... --headless --quit-after 600 --path D:\Qoder_game res://tests/test_p3.tscn
  ```
  期望末行 `结果：全部通过 [PASS]`，退出码 0。
- 断言覆盖：CSV 加载计数、凛 Lv1/Lv10 属性派生（与手算一致）、敌人加载、元素克制系数、经验曲线、AI/掉落查询。

**过程中解决的两个 Godot 坑**（备忘）
1. GDScript 用 `:=` 对字典取值推断类型会报错 → 改为显式类型声明。
2. Godot 默认把 CSV 当「翻译源」导入，生成 48 个 `.translation` → 已将每个 `.csv.import` 设为 `importer="keep"`，并修正 `.gitignore`（跟踪 `*.import` 配置、仅忽略 `.godot/` 缓存）。headless 首次测试前需先 `--import` 建立 `class_name` 全局类缓存。

## P4 · 战斗核心 MVP ✅

**做了什么**（逻辑层与表现层分离，便于测试与扩展）
- `scripts/battle/damage_calc.gd`：伤害/治疗计算器。实现护甲递减减伤公式 `DEF/(DEF+K)`（K=100+10×等级）、命中/闪避、暴击(1.5倍)、元素克制、±5% 浮动、最低伤害保底 1。
- `scripts/battle/turn_queue.gd`：速度行动条，按 SPD 降序排列（可加随机扰动）。
- `scripts/battle/battle_logic.gd`：纯逻辑战斗流程（回合推进、目标选择、胜负判定），不含 UI/计时器，可无头运行。
- `scripts/battle/battle_manager.gd` + `scenes/battle.tscn`：占位方块战斗场景（血条、伤害数字、暴击/未命中提示、攻击按钮、战斗日志）。
- `tests/test_p4.gd` + `test_p4.tscn`：7 组断言测试。
- `run_battle.bat`（启动战斗）、`run_tests.bat`（扩展为跑 P3+P4）。

**这一部分的作用**
全项目成败关键。战斗骨架（谁能打、打多少、谁先动、何时分胜负）跑通后，P5 起都是在此之上加技能/元素/状态与堆内容。逻辑与表现分离的架构，也让战斗规则可被自动化测试。

**可视化 / 可观察结果**
- 双击 `run_battle.bat`：窗口中蓝色方块=凛(Lv5)、红色方块=裂隙黏体，各有名字/血条/元素标签。
- 点【攻击】→ 敌方方块闪白、弹出红色伤害数字（暴击为金色、未命中显示 MISS）、血条与数字实时下降、左侧战斗日志滚动记录每次伤害（含减伤%与元素系数）。
- 敌方回合自动行动；一方血量归零即判定胜负并显示结果；可点【重新开始】再战。

**如何验证**
- 双击 `run_tests.bat`（或命令行跑 `res://tests/test_p4.tscn`），期望末行 `结果：全部通过 [PASS]`。
- 断言覆盖：物理伤害落在公式预期区间、魔法走 MATK、治疗量=power×MATK、高防保底伤害≥1、行动条按速度降序、完整战斗「凛 Lv5 胜裂隙黏体（约2回合）」与「澪 Lv1 败于裂隙核心」两种结局。

## P5 · 战斗系统扩展 ✅

**做了什么**（延续逻辑层/表现层分离，所有新系统都可无头单测）
- **数据表**：新增 `data/status_effects.csv`，把灼烧/回春/护盾/感电/冰冻/攻防增益的**具体数值**从代码里挪进表（kind + value），改平衡只改 CSV。DataManager 加载并提供 `get_status()`。
- `scripts/entities/status_effect.gd`：一个「已激活」状态实例（含剩余回合、护盾量）。
- `scripts/entities/unit.gd`：加入状态容器 + 护盾池 + **有效属性** `eff_atk/eff_matk/eff_def/eff_spd`（基础值×状态修正），以及回合开始结算(DoT/HoT)、回合递减与到期移除、感电跳过判定、护盾优先吸收的 `take_damage()`。
- `scripts/battle/skill_executor.gd`：技能结算器——扣蓝、按 `target` 选目标（单体默认取血量最低队友/首个敌人，可指定）、逐目标算伤害或治疗、按 `effect_chance` 施加状态、护盾吸收。
- `scripts/battle/enemy_ai.gd`：读 `enemy_ai.csv`，先按 condition（always / hp_below_50 / hp_below_30 / ally_hp_below_50）过滤候选，再按 weight 加权随机。**Boss 多阶段**即靠血量阈值解锁新技能实现。
- `scripts/entities/equip_calc.gd`：把一组装备的主/副词条汇总成加成并作用于角色；`scripts/entities/progression.gd`：经验累积与连升多级（读 `levels.csv`）。
- `scripts/battle/battle_logic.gd`：重构为「技能/状态/AI 驱动」，支持多我多敌；每步处理回合开始状态结算→感电跳过→选技能（玩家用指令、敌人用 AI，蓝不足退回普攻）→结算。
- `damage_calc.gd` / `turn_queue.gd`：改走**有效属性**，让增益/冰冻真正影响伤害与出手顺序。
- `battle_manager.gd` + `scenes/battle.tscn`：战斗场景升级为**三人队 vs 多敌**，含技能按钮（显示蓝耗、蓝不足置灰）、能量条、单体技能**点选目标**、状态图标实时显示、伤害/治疗/护盾/元素克制飘字。
- `tests/test_p5.gd` + `test_p5.tscn`：14 组断言；`run_tests.bat` 扩展为跑 P3+P4+P5。

**这一部分的作用**
把 P4 的「普攻对轰骨架」补成**完整可玩的战斗系统**：技能/元素克制/状态效果/装备/升级/敌人 AI/Boss 多阶段/多单位全部打通。这是能被称为「回合制 RPG」的核心，也是策划岗最能体现数值与系统设计深度的部分。所有数值仍进表，逻辑与表现分离，规则可被自动化验证。

**可视化 / 可观察结果**
- 双击 `run_battle.bat`：下排三个方块=凛/苍/澪(Lv6)，上排=裂隙黏体/异化蝠/失控炮台，各有名字·等级·元素、血条、**能量条**、状态图标行。
- 玩家回合底部出现**技能按钮**（普攻 + 各角色技能，标蓝耗）；点单体技能后需**点一个目标**，群体/自身技能直接生效。
- 敌方回合由 AI 自动决策：炮台会群体火焰吐息并可能给我方挂**灼烧**（每回合掉血飘橙字）、异化蝠的电火花可能**感电**（概率跳过行动），日志逐条记录元素系数、护盾吸收、状态施加与击败。
- 一方全灭即判定胜负，可【重新开始】。

**如何验证**
