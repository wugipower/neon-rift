# 《霓虹裂隙》开发方案（Game Design Document）

> 一款都市·二次元幻想题材的 **2D 回合制 RPG**
> 定位：秋招「游戏策划」岗位作品 · 单人开发 · 引擎 Godot 4 · 交付形态 Windows .exe（源码托管 GitHub）

---

## 0. 一句话概述

在近未来的霓虹都市，普通人偶觉醒「异能」，而城市裂缝中涌出的「异化体」正在侵蚀现实。玩家扮演一名刚觉醒的异能者，组建小队、探索据点、通过回合制战斗推进剧情，最终封印裂隙。

**核心卖点（对策划岗）**：完整的数值成长曲线 + 可推导的战斗公式 + 数据驱动的技能/装备系统 + 清晰的关卡节奏。技术极简，设计密度高。

---

## 1. 项目约束与目标

| 项目 | 约定 |
|---|---|
| 引擎 | Godot 4.x（免费、轻量、开源） |
| 开发语言 | GDScript（语法类 Python，易上手，与引擎深度集成） |
| 目标平台 | Windows 桌面 .exe（双击运行，免安装引擎） |
| 性能预算 | CPU < 10%、内存 < 500MB、稳定 60 FPS（远低于你 85% 的上限） |
| 你的配置 | i5-13500H / 16GB / RTX 3050 4GB —— 2D 回合制毫无压力 |
| 开发周期 | 约 2~3 周（业余时间），见第 9 节里程碑 |
| 素材 | 全部使用 CC0/免费授权素材或 AI 生成，规避版权风险 |

**设计原则**：宁可玩法简单但系统完整、数值自洽，也不要堆砌内容。评委看的是「你会不会做设计」，不是「你做了多少」。

## 2. 世界观与叙事（轻量，服务于玩法）

- **背景**：20XX 年，巨型都市「新曦市」。三年前「大裂隙事件」后，城市上空出现能量裂隙，部分市民觉醒异能（称为「回响者 Echo」），同时裂隙中渗出扭曲现实的怪物「异化体」。
- **主角**：一名刚觉醒的普通学生/上班族，被民间组织「霓虹事务所」收容，成为处理裂隙事件的异能者。
- **主线（精简为 3 幕）**：
  1. **觉醒**：教学关，主角首次战斗，学会基础操作，加入事务所。
  2. **调查**：探索城市 3 个区域，发现异化体失控背后有人为操控。
  3. **封印**：突入裂隙核心，击败幕后 Boss，封印裂隙。
- **叙事载体**：据点 NPC 对话 + 战斗前后短剧情 + 可收集「记忆碎片」（世界观补充，纯文本）。文案量控制在能讲清主线即可，不做长篇。

> 叙事是为玩法服务的骨架，不必写小说。策划岗更看重「剧情节奏如何与关卡难度曲线配合」。

## 3. 核心玩法循环（Core Loop）

```
   探索据点/地图
        │
        ▼
   触发遭遇战 ──► 回合制战斗 ──► 胜利：经验/素材/剧情
        ▲                              │
        │                              ▼
   失败：回到据点 ◄── 强化：升级 / 技能 / 装备 / 商店
        │                              │
        └──────────────────────────────┘
                   推进下一章节 / Boss
```

单局战斗时长目标：**2~4 分钟**。整体通关时长目标：**1.5~2.5 小时**（Demo 体量，完整不注水）。

## 4. 系统设计

### 4.1 属性系统

**一级属性（决定成长与派生）**

| 属性 | 缩写 | 作用 |
|---|---|---|
| 体质 | VIT | 决定 HP 上限 |
| 力量 | STR | 决定物理攻击 |
| 灵能 | INT | 决定异能（技能）攻击与 MP 上限 |
| 敏捷 | AGI | 决定速度、暴击率、闪避率 |

**二级属性（由一级派生）**

| 属性 | 派生公式（示例，可在 CSV 中调参） |
|---|---|
| HP 上限 | `100 + VIT * 12 + 等级 * 5` |
| MP 上限 | `30 + INT * 6 + 等级 * 2` |
| 物理攻击 ATK | `8 + STR * 2.0` |
| 异能攻击 MATK | `8 + INT * 2.0` |
| 防御 DEF | `5 + VIT * 1.0 + 等级 * 0.5` |
| 速度 SPD | `8 + AGI * 1.5` |
| 暴击率 CRT | `5% + AGI * 0.3%`（上限 50%） |
| 闪避率 EVA | `3% + AGI * 0.2%`（上限 25%） |

> 派生公式集中放在一个 `stats_formula` 表/脚本里，改一处全局生效 —— 这是「数据驱动」的体现。

### 4.2 回合制战斗系统

- **行动顺序**：所有单位按 SPD 从高到低排入「行动条」，SPD 相同则随机。每回合重算（可用速度值 + 少量随机扰动避免完全固定）。
- **玩家指令**：`攻击 / 异能（技能）/ 道具 / 防御 / 逃跑`。
- **防御**：本回合受到伤害减半，速度临时 +（用于抢节奏）。
- **胜负**：敌方全灭=胜；我方全灭=败（回到据点，不删档）。
- **战斗反馈**：伤害数字弹出、受击闪白、血条动画、元素克制提示（关键，让数值「看得见」）。

### 4.3 伤害公式（核心，面试常问）

采用**护甲减伤递减公式**（防御收益随数值递减，避免后期堆防无敌，是主流商业游戏的做法）：

```
减伤率 = DEF / (DEF + K)，其中 K = 100 + 10 * 攻击方等级
基础伤害 = 技能威力 * 攻击属性(ATK 或 MATK)
最终伤害 = 基础伤害 * (1 - 减伤率) * 元素克制系数 * 随机(0.95~1.05) * 暴击倍率
最低伤害 = 1（保证任何攻击都有效）
```

- **暴击**：命中暴击时 `暴击倍率 = 1.5`（可通过装备/技能提升）。
- **命中判定**：`命中率 = 100% + 攻击方命中 - 防守方闪避`，最低 50%。
- **元素克制系数**：克制 1.5 / 正常 1.0 / 被克 0.75（见 4.4）。

> 面试话术：「我用 DEF/(DEF+K) 而不是 DEF 直接相减，是因为线性减伤在高防御时会出现『零伤害』或收益爆炸，递减公式让每点防御的边际收益平滑下降，便于控制数值膨胀。」

### 4.4 元素系统（都市异能题材）

4 元素循环克制，简洁好记：

```
电 ──克──► 水 ──克──► 火 ──克──► 冰 ──克──► 电
（无属性/精神 不参与克制，恒为 1.0）
```

每个技能与每个敌人带一个元素标签，克制关系放 `elements.csv`，代码查表即可。

### 4.5 技能（异能）系统

- 每个角色 3~5 个异能，消耗 MP。
- 技能字段：`id / 名称 / 元素 / 威力 / MP消耗 / 目标类型(单敌·全体·单友·自身) / 附加状态 / 描述`。
- **状态效果**（增益/减益，持续 N 回合）：
  - 灼烧（每回合掉血）、感电（概率眩晕）、冰冻（减速）、
  - 攻击↑/防御↓、回复（每回合回血）、护盾（吸收伤害）。
- 全部技能数据存 `skills.csv`，新增技能不改代码。

### 4.6 装备系统

- 槽位：`武器 / 护甲 / 饰品`（各 1 件，简化）。
- 词条：主属性加成 + 至多 1 条副词条（如暴击 +5%、某元素伤害 +15%）。
- 装备数据存 `equipment.csv`，通过商店购买 / 战斗掉落获得。

### 4.7 成长与经验系统

- **升级经验曲线**（越往后越陡，控制节奏）：
  ```
  升到下一级所需 EXP = floor(50 * 等级^1.6)
  ```
  例：Lv1→2 需 50，Lv5→6 需 ~560，Lv10→11 需 ~1990。
- 升级时：属性按「角色成长率」自动提升（见 `characters.csv` 的 growth 列），并回满 HP/MP。
- 等级上限：Demo 设 **20 级**（够展示曲线，又不注水）。

### 4.8 敌人 AI（简单行为表）

- 每个敌人一张「行动权重表」：如 `普攻70% / 技能30%`，或「血量低于 30% 时必用大招」。
- 数据驱动，存 `enemies.csv` + `enemy_ai.csv`。
- Boss 设计多阶段（血量 50% 切换行为模式），制造节奏高点。

### 4.9 存档系统

- 在据点手动存档 + 战斗胜利后自动存档。
- 存 `user://save.json`（Godot 用户目录），记录：队伍等级/属性、背包、装备、剧情进度、金钱。

## 5. 数值设计（数据表清单）

所有数值用 **CSV** 存储，Godot 原生可读；用 **WPS 表格 / Excel / LibreOffice Calc** 编辑。

| 文件 | 内容 | 关键列 |
|---|---|---|
| `characters.csv` | 可玩角色基础值与成长率 | id, 名称, 基础VIT/STR/INT/AGI, 各属性成长率, 初始技能 |
| `levels.csv` | 每级所需经验 | level, exp_to_next |
| `skills.csv` | 异能技能 | id, 名称, 元素, 威力, mp, 目标, 状态效果, 描述 |
| `enemies.csv` | 敌人属性 | id, 名称, HP, ATK, DEF, SPD, 元素, 掉落id, exp, gold |
| `enemy_ai.csv` | 敌人行为权重 | enemy_id, 技能id, 权重, 触发条件 |
| `equipment.csv` | 装备词条 | id, 名称, 槽位, 主属性, 副词条, 价格 |
| `drops.csv` | 掉落表 | enemy_id, item_id, 概率 |
| `elements.csv` | 元素克制系数 | 攻方元素, 守方元素, 系数 |

**数值样张（角色基础值示例，实际存 CSV）**

| 角色 | 定位 | VIT | STR | INT | AGI | 成长倾向 |
|---|---|---|---|---|---|---|
| 主角·凛 | 均衡输出 | 10 | 12 | 10 | 11 | 全能 |
| 队友·苍 | 坦克/前排 | 15 | 11 | 6 | 7 | 高体质 |
| 队友·澪 | 灵能/辅助 | 7 | 6 | 15 | 10 | 高灵能 |

**平衡性验证方法**：建一张「战斗模拟表」，用公式验算「玩家 Lv5 队伍打某敌人需要几回合」「Boss 战是否控制在 8~12 回合」。把调参前后对比记录进 `docs/数值调优记录.md` —— 这是策划岗极强的加分项。

## 6. 内容与关卡规划（Demo 体量）

| 章节 | 场景 | 内容 | 敌方强度 |
|---|---|---|---|
| 序章 | 事务所（据点） | 教学、对话、存档、商店解锁 | 教学战（1 弱敌） |
| 第1章 | 废弃地铁站 | 2~3 场遭遇战，引入电/火元素 | Lv3~5 |
| 第2章 | 商业区屋顶 | 2~3 场战斗 + 中 Boss（多阶段） | Lv6~9 |
| 第3章 | 裂隙核心 | 精英战 + 最终 Boss（双阶段） | Lv10~13 |

- 关卡之间用「据点 → 选择区域 → 战斗 → 返回」的节点式地图推进（省去做大地图寻路，节省 80% 工作量）。
- 每个区域配 1 段短剧情 + 1 个可选支线（收集记忆碎片）。

## 7. Godot 工程结构

```
res://
├── project.godot              # 工程配置（窗口 1280x720，2D 渲染）
├── autoload/                  # 全局单例（Autoload）
│   ├── game_state.gd          # 存档、金钱、剧情进度、队伍数据
│   ├── data_manager.gd        # 启动时加载所有 CSV → 字典
│   └── scene_loader.gd        # 场景切换
├── scenes/
│   ├── main_menu.tscn         # 主菜单（开始/继续/退出）
│   ├── hub.tscn               # 据点（事务所：NPC/商店/存档/出发）
│   ├── battle.tscn            # 战斗主场景
│   └── ui/                    # 血条、对话框、战斗菜单、伤害数字
├── scripts/
│   ├── battle/
│   │   ├── battle_manager.gd  # 战斗主流程与状态机
│   │   ├── turn_queue.gd      # 速度行动条
│   │   ├── damage_calc.gd     # 伤害公式（4.3）
│   │   └── status_effect.gd   # 状态效果处理
│   └── entities/
│       ├── unit.gd            # 战斗单位基类（角色/敌人共用）
│       ├── player_unit.gd
│       └── enemy_unit.gd
├── data/                      # 所有 CSV（第 5 节）
├── assets/
│   ├── art/                   # 立绘、精灵、UI、背景
│   └── audio/                 # BGM、音效
└── docs/                      # 设计文档（也可放仓库根 docs/）
```

**关键实现顺序**：`data_manager 读 CSV` → `unit 属性派生` → `damage_calc` → `turn_queue` → `battle_manager 状态机` → 再挂 UI。先让「两个方块互相打、数字正确」跑通，再美化。

## 10. 美术与音频方案（零成本）

- **立绘/角色**：二次元风格可用免费素材站（如 itch.io 的 CC0 素材包）或 AI 生成，统一色调。
